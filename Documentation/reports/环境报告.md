### 版本选择依据

- **Unity 6000.0.85f2**：6000.0 是当前 LTS 主线中维护最久的一条，插件生态与文档最成熟。

- **JDK 17**：Unity 6000 的 Android 构建链（Gradle 8.x + AGP）要求 JDK 17。
  本机 PATH 默认的 Java 仍是 8，`JAVA_HOME` 指向 21；两者都不适用于 Unity 构建，
  因此工具链单独携带 JDK 17，通过 `tools/env.sh` 在会话内切换，不改系统变量。
- **NDK r27c（27.2.12479018）**：Unity 6000.0 的 IL2CPP 构建使用该版本。
  其他版本虽可能可用，但未经 Unity 验证，不作为基线。

## 4. 阻塞项

### 4.1 EsafeNet Cobra DocGuard 透明加密导致 C# 无法编译（**最高优先级阻塞**）

本机安装了企业透明加密客户端 `EsafeNet Cobra DocGuard Client`
（`C:\Program Files\EsafeNet\Cobra DocGuard Client\`）。实测它对文本文件
按 **512 字节阈值**自动加密：

| 文件大小 | Roslyn 编译器的读取结果 |
|---|---|
| ≤ 512 字节 | 正常 |
| > 512 字节 | 读出密文，报 `CS2015: is a binary file instead of a text file` |

复现方式（`Tools/pdl.py` 之外的最小编译验证）：

```bash
DOTNET=F:/WonderEnglish/tools/Editor/Data/NetCoreRuntime/dotnet.exe
CSC=F:/WonderEnglish/tools/Editor/Data/DotNetSdkRoslyn/csc.dll
# 20 字节文件 + C 盘 Temp → 正常（仅缺引用）
# 600 字节文件 + 任意路径 → CS2015
```

测量数据：390/440/470/490/502/510 字节均正常，530/550/590 字节全部失败，
阈值精确落在 512 字节。

**影响范围**：Unity 自带包的源码普遍在数 KB 量级（例如
`com.unity.ugui/Runtime/UGUI/UI/Core/GraphicRegistry.cs` 为 8084 字节），
因此包解析、C# 编译、Gradle 构建全部无法进行。工程自身源码同样受限。

**已确认无效的规避方式**：

- 换盘符（D/E/F 表现一致，C 盘 Temp 同样失败）
- 添加 UTF-8 BOM（文件内容本身可被 Python 正确读取，加密发生在驱动层）
- 改为 `file:` 本地包依赖（包解析可通过，但编译仍失败）
- 在 Temp 目录新建文件（超过 512 字节依然被加密）

**结论**：这项工作无法在代码层面绕过。需要由公司 IT 将工程目录与工具链
目录加入 DocGuard 白名单，或在该目录关闭透明加密。
