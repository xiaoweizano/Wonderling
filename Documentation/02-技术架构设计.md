# 02 技术架构设计

## 1. 总体架构

```text
Unity Presentation
  ├─ 3D Scene / Teacher / Animator
  └─ 2D UI / Task Views
          |
          v
C# Application & Course Engine
  ├─ LessonRunner / StepExecutor
  ├─ Task Registry / Task Handlers
  ├─ Teaching State Machine
  ├─ Adaptive Learning
  └─ Reward & Progress
          |
          v
C# Domain Interfaces
  ├─ IAudioService
  ├─ ISpeechService
  ├─ ICourseRepository
  ├─ IProgressRepository
  └─ IResourceProvider
          |
          +--------------------+
          |                    |
          v                    v
Unity Implementations     Android Kotlin Bridge
  ├─ Audio                ├─ Permission
  ├─ SQLite               ├─ Recorder
  ├─ Local Assets         ├─ VAD / ASR SDK
  └─ JSON                 └─ Lifecycle
```

## 2. 模块职责
### Presentation
负责显示和用户输入，不承载课程规则或数据库逻辑。

### Course Engine
读取课程定义，校验步骤，驱动步骤执行、状态迁移、暂停恢复和进度保存。

### Task System
每种任务独立实现 `ITaskHandler`，通过注册表按类型创建。任务只返回结果，不自行决定课程下一步。

### Services
提供音频、语音、数据库、资源和存储能力。通过接口隔离平台实现。

### Native Bridge
Kotlin 负责 Android 原生能力。C# 是调用方和业务决策方。

## 3. 推荐程序集
- `WonderEnglish.Core`
- `WonderEnglish.Domain`
- `WonderEnglish.CourseEngine`
- `WonderEnglish.Tasks`
- `WonderEnglish.Infrastructure`
- `WonderEnglish.Presentation`
- `WonderEnglish.AndroidBridge`
- `WonderEnglish.Tests`

依赖方向应由表现层/基础设施依赖领域抽象，领域层不得依赖 Unity UI 或 Android 具体实现。可按实际 Unity asmdef 依赖限制调整。

## 4. 关键接口
```csharp
public interface ITaskHandler
{
    string TaskType { get; }
    void Initialize(TaskContext context);
    void StartTask();
    void SubmitAnswer(TaskAnswer answer);
    void PauseTask();
    void ResumeTask();
    void Dispose();
}

public interface IAudioService
{
    void Play(string audioId);
    void Stop();
    void Pause();
    void Resume();
}

public interface ISpeechService
{
    Task InitializeAsync(CancellationToken token);
    Task StartRecordingAsync(CancellationToken token);
    Task<SpeechResult> StopRecordingAsync(CancellationToken token);
    Task DisposeAsync();
}
```

异步接口必须支持取消、错误返回和生命周期清理。实际代码可使用 `Task<Result<T>>` 或项目统一 Result 类型，避免异常成为正常控制流。

## 5. 课程运行状态
建议状态：
`Idle → LoadingCourse → PlayingStep → WaitingForInteraction → CheckingAnswer → Feedback → NextStep → Completed`

附加状态：
`Paused`、`Resuming`、`Error`、`Exiting`。

状态迁移必须集中管理，禁止 UI 按钮直接修改多个状态字段。

## 6. Android 桥接约定
- 使用 Unity `AndroidJavaObject` / `AndroidJavaClass` 调用 Kotlin 暴露的稳定 Facade。
- Kotlin 回调回 Unity 时必须切回 Unity 主线程后再更新 UI。
- 定义统一消息结构：请求 ID、操作类型、成功标记、错误码、结果数据。
- 处理权限拒绝、Activity 重建、应用进后台、录音中断、模型加载失败。
- Android 插件仅在 Android 平台编译；Editor 下提供 Mock 实现以便开发测试。

## 7. 资源策略
- 必需资源随安装包交付。
- Addressables 仅用于本地资源组织/加载，不配置远程 Catalog 或远程下载依赖。
- 资源清单应有 ID、路径、类型、校验信息和版本。
- 加载失败应显示可恢复错误，不允许空引用崩溃。
- 场景切换和任务结束后释放临时资源。

## 8. 性能策略
- URP；限制实时阴影、灯光数量、透明叠加和粒子。
- 角色与动物模型控制骨骼数、材质数和贴图分辨率。
- 优先使用烘焙光照和复用动画。
- 避免每帧分配对象；频繁对象使用对象池。
- 音频和语音推理不得阻塞主线程。
- 对语音模型加载峰值、场景切换峰值和长时间运行进行 Profiler 测试。

## 9. 风险与技术验证
优先验证 Unity Android 构建、Kotlin 插件调用、sherpa-onnx Android 兼容性、模型大小和内存峰值。验证未完成前，不锁定最终 ASR 模型和设备性能承诺。
